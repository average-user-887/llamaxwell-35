# Additional two-row sparse probe experiment

This opt-in CUDA change groups four original 256-key blocks in one 128-thread CTA. Each warp retains the same probe position in each of the four blocks and loads the eight query heads once. For each Q/K dot the eight-element FP32 multiply-add sequence and the original XOR offsets 16, 8, 4, 2, 1 remain in order. The warp partitions the head results across its lanes in the first three steps and completes each head in the last two. Ballots find each original block's last finite mask entry and invalid-mask flag. A separate invalid score flag is preserved. All original block entries are still produced.

The direct baseline is the actual 9e999bca CUDA library with its fast top-16 selector enabled in every timing arm. The native Q8 GDN and two-row MoE objects are identical, and all 34 preceding attention device functions retain their compiled instruction and scheduling words. Width one, top-16 selection, retained attention and output combine have their previous implementations. The additional opt-in is GGML_CUDA_OCCAMY_FA_Q2_R2_PROBE4=1 on the already-admitted aligned 80,128–83,200 range. At 81,920 keys there are 80 tile CTAs per plan instead of 320 block CTAs per plan. The new sm_52 function uses 96 registers, 256 bytes of static shared memory and zero spills.

The root-only 180-second operator compares four fresh fixed-seed processes in control/candidate/candidate/control order with the earlier unchanged operator executable. The first candidate call in each mirror independently replays the reference probes and selector, compares 1,280 raw metadata entries and raw score bits, four plans and all 8,192 output words, and exercises separate GPU masks containing NaN, positive infinity and a negative-infinity tail at probed, unprobed, old and recent positions. That extra adversarial check compares all raw metadata and scores, records the invalid blocks and leaves the measured tensors unchanged. The actual timing covers the entire operator, with diagnostics confined to the first call. The two candidate and two baseline process outputs must also agree byte for byte, and both measured improvements must reach at least 30 µs relative to the already optimized selector. Eight-expert model execution and 84,224 keys are outside this fixed-fixture card.

Use release.sh --check for offline validation. Under the root's admitted M6000 guard, release.sh --run checks the root deadline and exclusive lease. The integrated 80K time and resulting gap remain to be measured independently.
