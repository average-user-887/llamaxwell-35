# Four adjacent down-projection rows per Maxwell warp

This opt-in targets the fused two-token Occamy verifier on the Quadro M6000 sm_52 with all eight routed experts and the shared expert. The original admitted two-row cohort and its per-token scratch stay in place. Only its Phase C down projection changes. The executable operator uses the exact existing Q4_0 layout with one 288-byte row, 589,824-byte expert and a 1,152-byte aligned quartet. Distinct routed tensors, routes and activations remain private to their original token. Each warp fetches contiguous vectors from a single selected expert at a time. Every octet owns one adjacent row, and every lane owns one original 64-input dot unit. Shared-expert work now uses all 32 lanes. Nine full warp dots replace twelve warp-dots per four outputs. No down-projection weight bytes are eliminated.

The kernel keeps the existing explicit dot2c multiply/add ordering, route weights and shared gate. It computes each original weighted pair as fma(w0, dA, mul(w1, dB)), then fuses the shared term in the first rank group only. For each row it first adds virtual groups (0,2) and (1,3), then those two sums, then pairs of lanes at distances four, two and one. This reproduces the exact original lane-zero XOR butterfly before adding the residual. The CPU checker exhausts destination coverage and per-expert word addresses and compares the reduction expression structurally. It checks 256 independently seeded weighted FP32 reductions using libm fmaf. The GPU diagnostic independently requires bitwise-identical finite outputs, all 4,096 words per fixture including a second candidate run, and both ordered eight-expert lists against the seeded CPU reference, generic CUDA router, physical control and both candidate readbacks.

## Physical screen and model handoff

The GPU owner alone may run ROOT_GPU_DEADLINE_EPOCH=<lease-end-epoch> N3_GPU=<admitted-M6000-UUID> ./release.sh --run after a fresh owner lease. This takes the campaign lock, requires idle Fleetdash admission, bounds the operator and cleanup to 180 seconds and prints Q2_DOWN4_RECEIPT. The two CUDA processes separate diagnostic readbacks from timings. Each fixture warms both paths for 4,096 synchronized graph calls. Four timed batches of 32,768 calls follow, A/B/B/A on disjoint routes and B/A/A/B on five-overlap routes. At 160 µs per call the timed and warm graph calls total about 45 seconds. The script records Fleetdash SM and memory clocks by host epoch, retaining unknown values where unavailable. The summary shows ranges and medians for every measured window. Clocks are comparable if both clocks are observed and the larger-to-smaller median ratio is at most 1.02 in every mirror.
