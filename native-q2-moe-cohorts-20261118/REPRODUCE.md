# Two-row Qwen35B full MoE on Quadro M6000

This standalone experiment compares the same physical GGML graph under the N88 eight-expert production-shaped fixture. With GGML_CUDA_OCCAMY_N2SPLIT=1 both modes match one native two-row MoE graph. The control executes its existing row-0 V3 launch followed immediately by its existing row-1 V3 launch. The candidate computes both in one grid of 48 blocks, with 24 private blocks per row and 512 threads per block. Its second host callback is acknowledged only after the first really submitted both rows for the same match, context, input and output. Neither timing arm uses a concatenation or a graph split. The original router, eight ordered experts, shared expert, FP32 gate/up accumulation, down projection and residual update implement the same arithmetic for each row.

The target is sm_52, 24 SMs, H=2,048, exactly two contiguous FP32 rows, 256 routed experts, active eight, FF=512 and matching nonoverlapping or exactly aliased output. Admission also requires V3, the existing matcher, a nonconcurrent primary stream, no output override and the new GGML_CUDA_OCCAMY_MOE_Q2_COHORTS=1 flag. The dynamic occupancy query must admit at least two resident candidate CTAs on each SM. The two workspaces and barriers are independent. The second callback falls through to legacy handling without a matching first-call completion. All 16 prior MoE device functions and 42,664 instruction words are byte-verified. The candidate compiled to 63 registers, 96 static and 39,424 dynamic shared bytes per CTA with zero stack and spills. CPU enumeration verifies full router, gate/up and down row coverage for each group.

The original Q8 GDN object bcd063306ea65f5e8143a8d6501960dbfeda359f5b3a261d5d91d612c786eac0 remains byte-identical in both 147-object links. The complete control relink reproduces the actual N88 Q8 CUDA library 3b3c6db37769ee281b4bc357faf6016f34388d7270545d6b13bbc37777c79fdf. The standalone MoE fixture itself contains no GDN or draft-context node. Its parent-arm measurements cannot substitute for a model result with the candidate.

## Run and interpret

With the root-owned exclusive GPU lease and N3_GPU supplied by its existing admission helper, use `./release.sh --run`. The two processes for diagnostics and timings, cleanup and analysis share a 180-second bound. Use `./release.sh --check` for CPU-only release and parser checks. The graph-program mapping, actual loaded CUDA library and executable are pinned. The candidate, the two physical legacy row launches and the acknowledged second callback have separate counters. The process checks native graph input stability after every batch.

The deterministic fixtures yield zero and five common experts out of eight. CPU and generic GPU orderings and two real candidate router readbacks must agree for both rows. Each fixture compares all 4,096 outputs bit by bit and checks every element for finiteness; the repeated candidate must be identical too. The diagnostics also compare both true N2SPLIT row launches against the original V2 oracle. Direct candidate route readbacks and V2 checks are disabled in performance. Initial eight-run warmups are followed by 96 completed synchronous graph calls per interval. Independent routes use N2SPLIT/cohorts/cohorts/N2SPLIT; partial overlap uses the reversed order. The materiality test, frozen before GPU use, requires at least 50 µs against the real N2SPLIT control in every pair on both fixtures. Multiplying 50 µs by 40 layers projects 2 ms; this is not measured whole-model latency. A smaller number is recorded as a miss. Both physical statuses and incomplete intervals are kept for technical failures.

The runner prints Q2_COHORT_RECEIPT. See result.json for independently parseable measured intervals and portable-receipt.json for full typed chronology, correctness, runtime identity, numerical and timing results, or an early refusal. To replay existing results, run `python3 -B report.py --report RECEIPT`. To reproduce a partial portable result run `python3 -B report.py --export RECEIPT` after its status exists.

## Rebuild

The CUDA and host patches apply to occamy-fused.base.cu and operator.base.cpp. From this directory in the matching campaign layout, use `./build.sh`, `python3 -B prepare-host.py`, `./build-host.sh`, then `python3 -B verify-build.py`. The pinned CUDA builder uses no GPU or network and two low-priority CPUs. The CPU-only report check includes explicit nonidentical-word, missing-callback, unsupported occupancy and inadequate-speed negative cases. The inherited N88 Q8 GDN object and source tree are immutable inputs. Source, exact link commands and checksums are provided for independent package staging.

The portable compiler-source-mount and historical environment-receipt names use typed @PRIVATE_…@ substitutions. Run `python3 -B hydrate-source.py OUTPUT --private-inputs LOCAL.json` to reproduce the exact observed bytes from local authorized values. Omitting the mapping verifies the portable copies of the sources and lists the required keys.
