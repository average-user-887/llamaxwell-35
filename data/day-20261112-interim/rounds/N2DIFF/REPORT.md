# N2DIFF: what still differs at n_tokens=2 vs 1 (source read only, BUNDLE3 @2436f75)

Model is all-Q4_0 weights (gguf header read), F32 norms and router. Fused MoE (all 40 layers, incl. router + shared expert, occamy-fused.cu:541/ggml-cuda.cu:3960) and fused GDN (30 layers, qkv/gate/alpha/beta/ssm_out inside, occamy-gdn.cu) run per row, so the leftovers are the 10 full-attention layers plus the head. The dominant residual is the plain MUL_MAT path: for Q4_0 with ne11=2 ggml_cuda_mul_mat (ggml-cuda.cu:2130) takes mmvq (ne11<=8; MMQ/cuBLAS are not reached), but the template instantiation changes with ncols_dst: calc_nwarps (mmvq.cu:~455-475, GENERIC table) gives 1 warp at ncols 1 and 2 warps at ncols 2, so the K-loop partition (blocks_per_iter 16 vs 32, kbx=tid/2 stride) and the cross-warp tmp_shared add (mmvq.cu:~1003-1010) change the fp32 summation tree (verified in source; int dot sums are exact, only the float accumulation of per-block terms differs, so differences are ~1 ulp of fp32 per output row, not bitwise equal). Flash attention is the second source: occamy FA is applicable (Q->ne[1]==1, fattn-occamy.cu:621) because -np 2 without -kvu gives n_stream=2 (Q->ne[3]=2, llama-graph.cpp:37; kv_unified default false is verified in code, that the server leaves it false for explicit -np 2 is inferred), and nsplit = ceil(resident*waves/(nkvh*ns)) (fattn-occamy.cu:681) halves with ns=2, so the split-K partition and ofa_combine_kernel order (:566-575) differ from n=1 (verified). One-off: the lm head uses head_rowpack_sm52 only for ncols_dst==1 (mmvq.cu:1443); at 2 columns it falls to generic mmvq 2-warp (verified). Per-ulp differences then get amplified by downstream q8_1 re-quantization (roundf(xi/d) flips) in every later layer, so earliest and per-layer ops matter most (inferred; not measured).

## Ranked (per-layer first, once last)
1. attn q/k/v/o mmvq, 10 layers x 4 mats: nwarps 1 vs 2, different K-loop split + shared-mem add; not bitwise (mmvq.cu:455-475, 910-1010; verified). attn_qkv/gate/alpha/beta/ssm_out are inside GDN, so not these.
2. occamy FA decode, 10 layers: nsplit depends on ns (fattn-occamy.cu:679-682), reduction order of partial (m,l,o) in ofa_combine differs; not bitwise (verified). If kv_unified were true, Q->ne[1]=2 makes occamy FA inapplicable and stock tile/vec runs instead (larger diff; inferred scenario).
3. lm head (output.weight 2048x248320), once: rowpack warp-per-row (lane/2 stride 16) at n=1 vs generic 2-warp mmvq at n=2; summation tree differs; not bitwise (mmvq.cu:1395-1410, 1443; verified). Applied directly to logits, but only ulp-level.
4. rms_norm of attention layers/output_norm/q_norm/k_norm: n=1 uses rms_norm_mul_q8_1_row, n=2 uses the pair kernel (norm.cu:578-602, 905) or stock block kernel; arithmetic is textually identical (tid-strided sum, block_reduce<1024>), so likely bitwise equal (inferred; not run). q/k norm (ncols 256) is per-row stock, equal.
5. quantize_q8_1 (quantize.cu:54) per row/32-block, independent of ne11: bitwise equal (inferred).
6. gdn_fused2 vs n=1 gdn_fused: different kernel, "same per-sequence arithmetic" per source comments only; not audited, suspect only if residual remains (inferred). Also split2 returns false for sv<0 and falls to STATE_DIRECT n=2 (occamy-gdn.cu:1171); check debug counter.
7. elementwise (rope, adds, sigmoid mul, set_rows, get_rows): row independent, bitwise equal.
Suggested test: force nwarps=1 for ncols 2 (calc_nwarps case 2 -> 1) and FA nsplit computed with ns=1; expect most of the 0.00082 to go.
