# R2 compact and down4 reserve

R2 reuses every mapped R1 software artifact and the exact owned-child supervisor. The feature vector differs from R1 only in `GGML_CUDA_OCCAMY_MOE_Q2_DOWN4=1`, in shadow, native and serial. The CLI and request fixtures carry forward. Compact eligibility, two-row shadow comparison, byte accounting, old archive identity, acceptance totals, emitted output length, and token-bearing SSE checkpoints retain the R1 checks.

The original down4 residency and counter checks require forty physically executed down4 calls per offered native proposal. The same-build serial control requires zero phase deltas. Startup-only calls are counted separately. Compact guard and readback counts are validated independently. The R1 shadow result qualifies compact readback with down4 disabled. This combined profile requires its own physical shadow and exact pair if invoked.

The measured historical 97.28926 tok/s anchor requires more than 0.52128 ms saved per offer to exceed 100 tok/s at its unchanged yield. Standalone operator savings motivate reserving this case. The combined model latency and exactness are pending. This is a reserve for an R1 timed pair below 100 tok/s.

Verify `./release.sh --check`. If the reserve is needed, the GPU owner supplies the existing admitted selector and cutoff, then runs `./release.sh --run shadow`. Use `./release.sh --run native` and `./release.sh --run serial` after exact shadow qualification. The existing shared lock and 430-second cap apply to each arm. `./release.sh --compare SERIAL_RECEIPT NATIVE_RECEIPT` replays the exact pair. Source changes are confined to the typed profile, associated down4 validation and local runner identity. The CPU replay uses synthetic receipt copies.
