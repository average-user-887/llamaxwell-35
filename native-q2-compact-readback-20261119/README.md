# Compact verifier readback screen

A standalone, synthetic, one-device A/B of the proposed target output path for the pinned 80K native MTP1 baseline. The screen includes pinned host readback, stream completion and ordered host sample-and-accept for both acceptance outcomes. It does not load the model. The synthetic GPU working set rotates over 64 pairs of contiguous 248,320-wide F32 rows, verified larger than the selected M6000 L2. Both arms reuse matching host and sampler allocations within each trial.

- Control copies 1,986,560 B per offer and calls the actual pinned N40 `common_sampler_sample_and_accept_n` and CPU samplers. Standalone ABI shims supply raw rows, exact compiled model vocabulary size and suppression metadata to the original chain. A real CUDA stream synchronization precedes the sampler. The shims do not reproduce the model context’s repeated, already-synchronized getter overhead and cannot establish end-to-end model savings.
- Candidate uses two tiled sm_52 kernels, a 16 B pinned readback and the same ordered acceptance entry point with compact IDs. The synthetic host shim supplies one placeholder candidate for the stock backend-token branch. Scores are outside the compact mode contract. The candidate marks tied maxima, nonfinite raw values and all-masked rows and takes a fresh full copy of the exact same live device rows before invoking the CPU path. Probability and score-observer controls take the full copy from the outset. Five forced device edge cases and two raw-only guard cases run outside timing. The all-masked case uses a deliberately full device mask to exercise that fallback while the stock CPU still interprets the original live logits with the model's real mask.
- The exact real model EOG list came from the archived current runtime startup. The pinned GGUF metadata contains no additional `tokenizer.ggml.suppress_tokens`. The measured temp-zero, `ignore_eos=true` fixture therefore masks the five EOG IDs. Normal synthetic cases mix rows with and without a masked raw winner. The harness prints only aggregate measurements and flags.
- Two order mirrors run A-B then B-A. Each arm uses 64 warm-up calls and 256 measured calls, with 64 samples in each accept/reject and mask-case stratum. The gate is a net 550 µs per offer in each mirror and mask case, weighting accepted and rejected medians by 1,429 and 213. The physical run reports valid misses as results. A companion experiment can compare the four measured margins against its observed residual separately.

`./release.sh --check` verifies the frozen files and upstream identities. The GPU owner can invoke `./release.sh --run` with the existing admitted `N3_GPU` selector and shared lock. The launcher uses the pinned local runtime image, no networking and a 120-second whole-card cap. `./build.sh` uses the existing toolchain image with runc, no devices and no network. The model file is used locally only to read metadata during preparation. Its fingerprint and stat provenance come from the existing campaign. The standalone test does not rehash or map model weights at runtime.

If the standalone gate warrants integration, use an opt-in compact output channel from one native MTP1 Q2 target graph. Keep its projection and target state unchanged. Gate before graph dispatch on the exact stateless temp-zero sampler, only the merged exclusion mask, no requested scores/probabilities, no observer and no replay. Keep raw logits reachable on-device until the two compact records have been checked and any required full copy is complete. Feed their IDs to the ordered CPU sample-and-match branch without altering sampler acceptance or trim rules. Count raw and compact bytes and observed fallback causes. The score observer requires the full live F32 vocabulary for normalization. Keep ordinary serial, prefill, tail and fallback paths eligible for their original readback. Check byte-for-byte decision parity in a separate raw-retaining shadow trial before the matched native/serial benchmark. Existing long-context repetition still needs its independent score audit.
