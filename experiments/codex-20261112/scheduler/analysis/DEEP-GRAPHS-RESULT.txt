DEEP TWO-SLOT CUDA GRAPHS: CURRENT BUNDLE3 PATH FAILS CAPTURE
2026-11-12. CPU-only source/evidence closeout; no fix, build or GPU launch.

DECISION
Do not enable GGML_CUDA_MAXWELL_GRAPHS for the current BUNDLE3 N2SPLIT
serving combination. The paired ON run aborts during capture, not merely
with a small timing regression. No graph-on throughput or quality result
exists. Earlier E07 replay evidence does not qualify BUNDLE3 N2SPLIT.
Leave the Maxwell graph override absent; setting it to "0" still enables
the presence-based architecture override.

SOURCE-GROUNDED CAUSE
Source paths below are relative to prefill/gemm/integration-v4/src/.
ggml/src/ggml-cuda/ggml-cuda.cu:2836-2866 checks MUL_MAT_ID synchronization
compatibility but does not reject the N2SPLIT host readback path.
Its line 3812 invokes ggml_cuda_occamy_gdn_split2 for a matched two-sequence
window; lines 5275-5277 flush staged inputs and advance the GDN generation.
Lines 5298-5300 mark capture ready, and line 5325 starts relaxed capture
on the compute stream before evaluating the graph.

ggml/src/ggml-cuda/occamy-gdn.cu:1151-1165 increments a per-compute generation
and caches two s_copy values on the host once per generation/input pointer.
The refresh performs device-to-host cudaMemcpyAsync followed by
cudaStreamSynchronize on that same capturing stream. The observed failure
is exactly this synchronization, not the new attention GEMM (disabled here).

WHY "CACHE IT ONCE" OR "REMOVE THE SYNC" IS NOT A CORRECT FIX
s_copy is mutable recurrent-state row-selection data, not constant model
metadata. src/llama-graph.cpp:1208-1215 refreshes it from recurrent memory;
can_reuse at 1230-1235 checks shape, head and zero-row metadata, not the
contents of the row-selection array. src/llama-memory-recurrent.cpp:1368
derives it from state cells and replay/checkpoint indexing.

occamy-gdn.cu:1176 branches on the HOST values to omit or include a gather;
1182-1183 hard-code source addresses using those values into CUDA memcpy
nodes. A graph captured for [head, head+1] omits gather entirely. If later
row selections change to a reorder, fork [r,r] or zeroed joiner, replaying
that graph would still use the captured branch and addresses. This is a
source-proven hazard of the proposed bypass, not an observed silent-error
result from the aborted run.

ggml-cuda.cu:2879-2883 treats matching graph UID as no property update;
4980 skips host graph traversal on replay, and 5245 launches the stored
graph. Advancing the host cache generation does not execute split2 again
during replay. Moving the host read outside capture only at initial capture
therefore does not solve dynamic row selection. Dropping synchronization
also permits stale host values before an asynchronous copy completes.

REAL FIX OPTIONS, NOT IMPLEMENTED OR VALIDATED
1. Preferred replay-safe design: make the row selection device data. Capture
   a GPU gather which reads current s_copy on every execution, gathers BOTH
   conv/SSM source rows into temporary storage before either destination is
   overwritten, then copies/uses the staged rows and launches paired GDN.
   Preserve current zero-row-before-gather ordering and bounds/eligibility
   semantics. Two-phase staging is essential for reorder and [r,r] aliasing;
   an unsynchronized in-place gather is not equivalent. Ensure captured
   temporary addresses and initialization remain valid across replay.
2. Alternative: validate current host-side row selections before every
   replay and include all capture-time branching/address data in the graph
   key or executable update/invalidation contract. Input ordering and
   graph lifetime must be explicit; any required readback/sync is outside
   capture and its overhead must be included. This is not a cache-once fix.
3. Conservative containment: reject graph capture for incompatible N2SPLIT
   windows before BeginCapture and execute eagerly. The existing global
   graph-off default already avoids this crash; a narrower compatibility
   guard is a future code change, not applied here.

Any real fix needs paired replay checks covering identity rows, swaps,
copy/fork, joining/reset slots and checkpoint rollback, including recurrent
state/output equality and scratch lifetime. Audit other lazy initialization
on the captured path too. Historical single/shallow E07 qualification and
successful single-sequence warmup cannot replace those tests. The previous
prefill/GRAPH-HISTORY.txt was a provisional pre-run assessment; this current
failed experiment supersedes its "no source blocker identified" statement.
