V4 SOURCE / GUARD INTEGRITY
Compared with BUNDLE3, fattn.cu adds only the new header include and a default-off early dispatch call. The original tile/common headers hash-identically; all failed candidate guards continue to the existing Occamy/stock dispatcher.
Guard requires SM520, F32 Q/output, F16 K/V, D256, 16 Q / 2 KV heads, all sequence dimensions one, Q64..1024, K4096..98304, compatible actual mask/strides, contiguous output, no sinks/ALiBi/softcap/sparse mode and finite scale.
Both-decode multi-sequence attention falls back twice over: Q is below 64 and ne3>1. A single-sequence decode also falls back. Genuine two-stream prefill falls back by ne3.
Mixed scheduling can expose a single-sequence prefill of Q1022 or Q1023; both satisfy the guard. Packing rounds to 1024, fills unused columns with zero, softmax zeroes those columns, and reduction suppresses writes outside actual Q. Slot numbers are not used as tensor indices; actual view base pointers/strides select the right slot.
The source does not truncate context: K above 98304 falls back, and supported K tails use a separate tail SGEMM. The same actual additive mask is applied in both softmax passes.
All-masked query output zero is an intentional edge behavior differing from the direct stock tile's 0/0. Nonfinite source tensors or NaN/+inf masks are not qualified by the synthetic or real tests.

ALLOCATOR / STREAM LIFETIME
The slab is a local ggml_cuda_pool_alloc<char>, not a shared global buffer. Context pools, cuBLAS handles and cuBLAS workspaces are indexed by device AND curr_stream_no (common.cuh:1451,1548,1570).
Conversion, Q packing, pointer setup, QK, softmax, PV and output reduction all enqueue on ctx.stream(); the handle is permanently bound to that same stream when created. There is no separately launched default-stream kernel in the candidate.
The device pointer table is initialized before use; its values point into the same slab and do not change between KV groups. Group 1 overwrites K/V only after every group-0 query tile has enqueued its PV/reduction in the same stream.
RAII destruction returns the allocation to the VMM stack after enqueue, but does not unmap the physical storage. Later reuse on that pool's same stream is ordered after earlier consumers. This matches existing backend temporary-allocation practice (common.cuh:1219; ggml-cuda.cu:565,670).
The server's single start_loop invokes update_slots once per iteration for all slots (server-queue.cpp:278,310). Two concurrent HTTP requests do not independently execute two host graph traversals on the same context.
No shared-slab race was identified under this serving model. This is source reasoning, not a race-detector result, and does not make concurrent external host calls into one backend context thread-safe.
Separate backend contexts or optimized graph streams would get separate pools and may each retain a slab; 412 MiB is per used context/stream, not a process-global maximum. Current saved routes omit both GGML_CUDA_MAXWELL_GRAPHS and GGML_CUDA_GRAPH_OPT, so that untested concurrency regime is not activated.
CUDA graphs are disabled below Volta unless GGML_CUDA_MAXWELL_GRAPHS is present (ggml-cuda.cu:5258). Server 'graphs reused' counters alone do not demonstrate CUDA graph replay.
The current v4 slab requests 432013888 bytes, pool-aligned to 432013952, plus the backend's existing 4 MiB cuBLAS workspace. The observed v4 2-slot profile, not multiplication by two HTTP requests, is the memory evidence. Capacity estimates remain workload- and output-count-specific.

REMAINING BOTTLENECKS / NEXT DECISIONS
The standalone online-softmax receipt around 98K attributes approximately 161 ms to QK, 150 ms to PV, 91 ms to softmax, 2.4 ms to conversion and 1.5 ms to reduction, of about 406 ms total. This stage profile uses synthetic causal data, not a measured breakdown of the integrated real-mask operator.
Consequently another conversion-only change cannot plausibly remove a large fraction of current operator time. Q8 direct conversion remains principally a capacity idea; see Q8_FORWARD_LOOK.txt.
The materialized score matrix is written by QK, scanned twice by softmax, then consumed by PV. Shared memory and SM52 register limits defeated the earlier naive tile/config sweeps; redoing occupancy-only sweeps is not supported by evidence.
Possible next algorithm work: retain packed GQA reuse while reducing score traffic, improve PV split/shape efficiency, or consume masks without redundant work. These require new measurements and precision checks, not a promised multiplicative speedup.
Allocator guards and two-stream fallback prevent current GEMM from covering every serving phase. That coverage limit should be reported, not averaged away.
Neither closer CPU-double samples nor one byte-identical real copy-edit proves general model-quality equivalence. The real distribution drift, OFF/OFF reproducibility controls and deeper task evidence remain separate acceptance questions.
