Strict publication boundaries
Exclude route.yaml/router.log, credentials, .env files, private keys, model
weights, saved slots, raw source/build trees, ownership snapshots, user rollout
excerpts, all bytecode-incident/backup files and speculation/quality-guidance.txt.
Do not publish arbitrary files merely because a text scanner finds no secret.
Use exact allowed GGML environment keys and validated boolean/numeric values,
not an unrestricted GGML-prefix rule. Preserve probability vectors and
measurement numbers; retain a redaction manifest and post-redaction hashes.

Recommended supplemental scan rules
Scan PEM private-key headers, GitHub tokens, sk- provider keys, AWS access IDs,
Google API keys, Slack tokens, JWT-shaped values, credentialed URLs,
Authorization Bearer/Basic values, quoted password/API/access/refresh/client
secret assignments, hf_ tokens and credential-bearing URL query values.
For JSON, scan both raw bytes and decoded string values. Report only rule,
path and count/offset/hash, never matched credential values. Word "token", model
token IDs and probability distributions are not intrinsically credentials.
Generic assignment/query rules need human review; scanner absence is not proof.
