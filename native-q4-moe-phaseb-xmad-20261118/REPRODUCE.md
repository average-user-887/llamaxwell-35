# Maxwell integer gate and up projections for four-row Qwen35B MoE

The new opt-in kernel evaluates the gate and up projections on signed Q8_1 activations while retaining all eight routed experts and the shared expert. Each 512-thread CTA computes its normalized input and FP32 router as in the preceding cohort kernel. Once the router partials are complete, the CTA packs one 2048-element row into the upper 4,096 bytes of the existing activation slab and records 64 pairs of FP16-rounded scales and sums in 512 shared bytes. It consumes these values across all gate/up rows assigned to that CTA. Two signed Maxwell XMAD instructions multiply two pairs of nibbles and activation lanes. Per-block FP32 rescaling precedes the same warp reduction, SiLU and multiplication. Q4_0 weights keep their original 18-byte layout. The unchanged down projection consumes the new intermediate activations and performs the original residual update. The arithmetic differs from the preceding FP32-activation V3 kernel. 

The eligible path uses the full eight-expert match, the existing Q4 cohort flag and GGML_CUDA_OCCAMY_MOE_Q4_PHASEB_XMAD=1. The stock cohort guard restricts the path to four contiguous 2,048-wide rows, eight 512-wide routed experts, the 512-wide shared expert, primary nonconcurrent stream and sm_52. The candidate has its own exact occupancy query with 48 resident CTAs required on 24 SMs. Admission failure retains the four-row cohort dispatch. All 18 prior device functions and 49,336 instruction words in the MoE object match the existing object. A separate control relink matches the combined abe7 library byte for byte. The new kernel uses 62 registers, no stack or spills and the original 39,424 dynamic shared bytes. The object contains 134 signed XMAD instructions. The zero-stack build evidence is in build.json. Physical occupancy is checked again on the GPU.

## Standalone operator

Run `./release.sh --check` for CPU checks. In the root-owned admitted GPU lease run `./release.sh --run`. This is one standalone experiment with a total cap of 180 seconds and separate diagnostics and timing. It needs the existing exclusive runner and its N3_GPU. The two original four-row fixtures have six zero pair overlaps and partial overlaps of 5/4/4/2/5/3. The independent CPU rankings, generic GPU router and direct candidate readback must match every ordered expert. The candidate must produce bitwise-repeatable outputs. The original cohorts must still match the four independent V3 rows exactly. The full generic, previous V3, new candidate, both full row outputs, and an independent generic Phase B graph are exercised on both fixtures. Check mode reads the physical post-SiLU gate/up scratch for all 4,608 elements per row (eight ranks plus shared expert) and compares it to the independent graph. The intermediate RMS and peak are descriptive. Timing disables all direct readbacks and uses quiet mode.

Before any GPU run, per-row candidate relative RMS against the generic result is bounded by that row's measured original V3 relative RMS plus 0.005. Absolute peak against generic is bounded by the baseline maximum plus 0.015. Against previous V3, RMS relative to its full residual output must be at most 0.05 and absolute peak at most 0.15. All 2,048 output values per row must be finite. The synthetic inputs lie in [-1,1]; peak bounds are in fixture output units. Raw maximum, relative RMS and changed-word counts are preserved. The full residual norm is the denominator for these gates; the isolated Phase B comparison supplies an additional read on the transformed quantity.

Timing uses synchronized whole-graph wall time, eight warmup runs in each mode and 96 completed runs per interval in cohorts, XMAD, XMAD, cohorts order for each geometry. An independent counter must increment on every intended physical launch and stay zero in its control. The incremental materiality gate requires a saving of at least 50 microseconds per layer in both directions on both fixtures compared with the already accelerated four-row cohorts. The corresponding 2 ms across forty layers is a projection. A technical measurement below that threshold is retained, as is a numerical refusal before any timing. This standalone program has no recurrent state or real prompt.

## Reproduction and evidence

The direct source delta is candidate.patch, based on occamy-fused.base.cu. The operator comes from operator.base.cpp and operator.patch. The standalone arithmetic is in xmad.inc and in the generated TU. Build with `./build.sh`, `python3 -B prepare-host.py`, `./build-host.sh`, then `python3 -B verify-build.py`. The CPU compiler container has no GPU or network and uses two CPUs with nice 19. The build relinks the two verified objects of the same 147-object combined runtime. The GPU release performs no compilation. Source digests, operator and runtime digests, original relink proof, SASS comparison, fixture and parser checks are frozen.

The runner prints Q4_XMAD_RECEIPT. Its portable-receipt.json carries actual numerical lines, ordered expert indices, comparisons, all physical warmup and timed intervals, refusal or completion and cleanup. A completed result can be recomputed with `python3 -B report.py --report RECEIPT`. On an interrupted or declined run use `python3 -B report.py --export RECEIPT` after status.txt exists. No performance claim follows from a CPU build.

The publication uses typed placeholders for the historical compiler source mount and the original baseline-run name where those arguments appear in commands. `python3 -B hydrate-source.py OUTPUT --private-inputs LOCAL.json` restores authorized local values and checks the resulting file against its original SHA-256. Invoking it without the local mapping verifies the portable source and displays required names. The actual hardware result is in operator.receipt.json.
