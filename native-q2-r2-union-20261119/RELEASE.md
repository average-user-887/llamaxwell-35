# Two-row F16 sparse union attention

This default-off derivative of the 369c6b CUDA library preserves the existing tile4 probe, ranking, four row/head plans, eight experts and F16 K/V. It replaces the retained operator on two query rows, two KV heads, 80,128 to 83,200 aligned keys, 1,024- or 2,048-byte K/V token pitch, 512-byte head pitch and the previous twelve-split stride dispatch. Enable the existing top16, tile4 and stride flags plus GGML_CUDA_OCCAMY_FA_Q2_R2_UNION=1. Unset the new flag to restore original dispatch.

A 128-thread CTA visits 16-key tiles from a tagged union. Each warp loads four distinct physical K vectors, reuses each Q coordinate across four token dots and computes eight heads per active row. The same threads then partition all 256 output dimensions and update all active heads from one load per V element. Shared memory contains Q and the tile scores. Split FP32 maxima and normalization use the original exponential base. The split order changes. This treatment retains the exact index policy, with a preregistered floating-point tolerance. Each valid KV head has 24 work splits. If either of its plans fails validation or exceeds supported recent-page geometry, its two rows use the original twelve-split primitive with their respective full/sparse policies. The device combine selects the compatible count for each KV head. A guarded fallback launch is part of every candidate timing.

The CUDA build relinked the archived input object to a byte-identical 369c6b control. All 37 original device functions matched all 55,480 executable and scheduling words. The final union specializations use 128 registers, 17,884 bytes shared, zero spill bytes and zero stack bytes. The CPU test covers 416 paired plans, 13 widths, holes, overlapping and disjoint old/recent pages, unequal ends, peak scores and masked tile normalization. CPU verification cannot establish numerical behavior or speed on the device.

The unchanged packed model uses 1,024-byte pitch. The standalone harness adds real dense allocation for 80,128, 81,920 and 83,200, including equivalent logical Q/K/V values and masks from the original padded 81,920 fixture. Dense draws skip the exact PRNG values occupied by the padded tensor's gaps. The parent runner alone may execute release.sh --run under its current benchmark lease, original full CUDA profile, Fleet admission and a 180-second cap including cleanup. release.sh --check is CPU only.

The seven fresh processes consist of dense 81,920 control/candidate/candidate/control, then dense candidate 80,128 and 83,200 and padded candidate 81,920. Each candidate's first call independently replays the old probe/selection and retained baseline, compares every score and plan, checks 8,192 finite output coordinates, and forces one invalid row/head in a separate buffer. The affected KV head's 4,096 outputs must be bitwise identical in the mixed fallback. Its sibling head still uses the new union. The two numerical criteria are |candidate-reference| <= 1e-5 + 1e-4*|reference| at each element and sqrt(sum(error²)/sum(reference²)) <= 1e-5. Edge-mask diagnostics retain the original NaN, positive infinity and causal-padding probes. The scoring and fallback diagnostics precede warmed full-operator timing. Repeated arrays must match within each arm, and dense/padded controls must reproduce the archived fixture hash.

The standalone screen requires at least 70 µs savings in each matched dense 81,920 mirror. At least 50 µs per mirror is a separate compound screen and needs an independently measured current companion saving at least 0.190 ms/round before model admission. No current companion is established here. Only an actual full-eight, 80K, one-slot matched native MTP1/server run plus scored long recall and repetition/output quality can substantiate throughput above 100 tok/s. The card changes no cache dtype, deployed service or server binary.
