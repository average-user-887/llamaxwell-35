# Exact paired gate and up projections for the two-row Maxwell verifier

This experimental kernel interleaves the original FP32 gate and up accumulators for each expert output row. Both projections use the same normalized activation vectors for a given token. Gate and up weights are unchanged. The previous kernel reads each vector separately while computing each projection. Each lane retains its original input order, its two ordered 32-term FMA chains per projection, FP16 scales, FP32 scale correction and butterfly reduction. Phase A and C are copied verbatim. All eight selected experts and the shared expert are computed separately for each token. The arithmetic is intended to match the 19607daf two-row verifier, including its unchanged N82 Q8 GDN on a model run.

The compiled Phase B loop contains 16 vector shared loads versus 32 in the original, with the same 134 FFMA instructions, 136 PRMT, 9 global load instructions and 10 butterfly shuffle instructions. These are static loop counts. Weight traffic and expert ranks are unchanged. An interleaved loop can hide dependent FMA latency as well as reduce shared-memory instructions. Its up-front need for both weights and its later next-row prefetch can offset those gains. Projected 25 µs savings per layer would be 1 ms across 40 layers. Physical performance is open. The original cohort timings were 162.63–162.65 µs on independent routes and 159.11–159.83 µs on partial overlap, so the gate requires about 15–16% improvement over those references.

## Build and admission

Run bash build.sh, python3 -B prepare-host.py, bash build-host.sh, and python3 -B verify-build.py. The control link must reproduce 19607daf exactly. The other 146 objects, including the Q8 GDN object, are shared across links. The added kernel uses 63 registers, 96 static and 39424 dynamic shared bytes and no stack or spills. All 17 existing device functions retain identical instruction and scheduling words. The source map is occamy-fused.base.cu plus candidate.patch for the CUDA change and operator.base.cpp plus operator.patch for its host harness. The offline frontend requires both original cohort admission and GGML_CUDA_OCCAMY_MOE_Q2_GATE_UP=1 for the candidate. The live per-kernel occupancy query must return at least two 512-thread CTAs on each of 24 SMs. On an unsupported configuration, normal runtime dispatch keeps the previously admitted path.

## Physical decision

Use ./release.sh --check to validate the frozen package and synthetic analyzer tests. For the sole GPU owner, ./release.sh --run with N3_GPU from the admitted runtime takes the benchmark lock and gives diagnostics, timing, analysis and cleanup a 180-second cap. The exact measured executable and CUDA library are identified inside the process. Both paths use the same native two-row GGML graph, the same candidate DSO and the same input. Control launches the original two-cohort function. Candidate launches the new function, with a separate physical issue counter and observed second-callback acknowledgments. Normal timing disables every route readback. Fixtures use independently derived deterministic ordered top-eight routes for each token with zero and five common experts. Diagnostics require all 4096 output words on each fixture to be finite and bit-identical to control and a repeated candidate. Direct router readbacks must match the CPU and generic GPU references for control and both candidate executions.

For each fixture, execute two eight-call warmups then four synchronous batches of 96 calls with mirrored order across fixtures. Advance on a minimum 25 µs reduction in all four paired intervals. Results below the gate, including genuine partial improvements, remain in the receipt. Stop on an identity, dispatch, occupancy, exactness or timing failure. The operator has no model, no draft and no recurrent node. Whole-model and serial gains require their own measurements.
