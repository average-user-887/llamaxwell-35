# Bounded expert byte offsets for two-row Maxwell MoE

This opt-in replaces only the gate/up and down weight addressing inside the validated two-row cohort. Each per-block routing warp calculates eight unsigned 32-bit offsets after producing the ordered IDs. All three routed tensors use an expert pitch of 589,824 bytes. The last legal vector starts at byte 150,994,928 and ends at 150,994,943. The model matcher requires contiguous Q4_0 tensors of the original fixed dimensions and 16-byte alignment. The original 64-bit device pointers carry the relative offsets. Both rows retain separate routing, scratch, grid barriers, prefetch order, full shared expert and all eight selected experts. The candidate requires the original admitted Maxwell Q2 cohort and GGML_CUDA_OCCAMY_MOE_Q2_OFFSETS=1. Original dispatch handles the default case or failed residency. Rollback uses the existing mode or the confirmed parent library.

The control relink must exactly reproduce 369c6b05; the current server remains 4a0ff82d. The original MoE device functions and instruction/scheduling words, retained fixed-stride attention object and Q8 GDN object are checked in verify-build.py. The added function uses 63 registers, 128 static and 39,424 dynamic shared bytes, and no stack or spills. The compiled Phase B loop falls from 566 to 494 instructions and 44 to 6 XMAD. Phase C falls from 774 to 673 and 56 to 14 XMAD. All checked floating-point, shuffle, quant unpack and global load instruction counts match between loops. These are static counts.

The operator compares the original cohort and the added kernel on the same graph and same DSO. It checks the actual two ordered eight-expert routes on each fixture against the independently seeded reference, all 4,096 finite output words of each fixture and both candidate repeats, candidate launch and acknowledgment counts, and actual residency of 48 blocks with 512 threads on 24 SMs. Numerical diagnostics and timed batches use separate processes and the latter disable routing readbacks. Timings include synchronized complete graph calls. The independent fixture uses A/B/B/A and the five-overlap fixture B/A/A/B after warmups, with 96 calls per interval.

Advance the standalone candidate only if the original-minus-candidate saving reaches 18 microseconds/layer in each of the four paired intervals. Forty layers would project to 0.720 ms at complete transfer. Report a separate conditional screen if every pair exceeds 13.7 microseconds/layer. That screen only supports a combination once an independent exact 0.16 ms/round draft gain is demonstrated on the current model trajectory. Real 80K throughput and model quality require a separate arm.

Rebuild locally with bash build.sh, python3 -B prepare-host.py, bash build-host.sh, python3 -B verify-build.py, then compare the generated identity with build.json. Run ./release.sh --check for offline verification. The GPU owner runs N3_GPU=<admitted device> ./release.sh --run under the existing Fleetdash admission and exclusive benchmark lock. The operator stages have a shared 180-second cap. The generated portable-receipt.json records status, actual device counters, full timings, numerics, threshold decisions and build identities; the raw logs remain beside it. Operator flags do not start a model.
